# Flowlets: advanced reference

You rarely need this file. The `flowlet` tool's description is the contract
for everyday screens, and the running core answers the rest:

- `flowlet(action="create", template_id="meals", lang="tr", pinned=true,
  watches=[{"preset": "daily_summary"}])` — a finished screen plus its evening
  summary in one call. Other templates: `water`, `habits`, `expenses`, `tasks`,
  `sleep`, `mood`; `flowlet(action="templates")` lists them with their
  ready-made reminders.
- `flowlet(action="create", definition={...})` for anything else, written
  straight from the tool description. Every problem comes back in one reply;
  slips with a single meaning are repaired and listed under `normalized`.
- `flowlet(action="guide")` — the full component catalog generated by the
  running core. `flowlet(action="template", template_id=...)` — an editable
  example.
- `list` / `get` are the inventory. Memory is not: never claim a screen exists
  from memory alone.

Do not search the filesystem, reread this skill, or use shell commands to
discover the API.

## When to read the reference

Read `skill_view(name="flowlets", file_path="references/catalog.md")` only for:
live `sources` (agent-fed data on a schedule), drill-down `screens`, data-bound
`table`s with search/sort, multi-series or categorical charts, `agent` action
buttons, `notify.compose` reminders written by the agent at fire time, and
`once`-latched buttons. Everything else is in the tool description.

## Rules that hold everywhere

- Reminders belong to the flowlet (`watches`), never to a cron job — a watch
  costs no model turn. Cron is only for outside lookups or reasoning across
  several flowlets.
- Times and "today" use the time zone of the device the user last opened the
  screen on (the host's own zone until then).
- Totals and charts read the same list the user edits; no shadow series.
- Never fill real state with sample data, and never remove a requested feature
  to get past validation.
