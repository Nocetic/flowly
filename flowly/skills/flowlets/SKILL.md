# Flowlets: create in one call

Use the `flowlet` tool directly. The runtime owns the catalog, validation,
rendering and reminders. Do not search the filesystem, reread this skill,
or use shell commands to discover its API.

## Standard screens

`flowlet(action="create", template_id="meals", lang="tr", pinned=true)` creates
a photo calorie journal with manual entry, editable rows, daily totals and
history. Other templates: `water`, `habits`, `expenses`, `tasks`, `sleep`, `mood`.
Use the user's language (`en`, `tr`, `es`). Supply `name` if requested.
`flowlet(action="templates")` lists templates when needed.

Template creation adds no reminders unless requested. Supply `watches` in the
SAME create call for a requested reminder or summary:
```json
{"action":"create","template_id":"meals","lang":"tr","pinned":true,
 "watches":[{"id":"evening","trigger":"schedule","at":"21:00",
 "notify":{"title":"Günlük özet","body":"Bugün {today_kcal} kcal; {meal_count} öğün."}}]}
```
Times and day boundaries use the execution host's local timezone. State the
chosen time when the user left it open. Templated summaries need no model turn,
extra skill or cron job. Cron is for external lookups or cross-flowlet reasoning.

## Custom screens and edits

- `flowlet(action="template", template_id=..., lang=...)` returns a complete
  editable definition without saving. Adapt then create.
- For new shapes, call `flowlet(action="guide")` ONCE for the current contract,
  component names, binds and limits, generated by the running core.
- For existing screens, use `list` then `get` and `update`. Memory is not an
  inventory: never claim a screen exists from memory alone.
- `create`/`update` validate before saving and return authoritative ID, live
  values and advisory lint/preview. No extra get is needed to confirm success.
  Fix material findings together in one update. Never remove requested features
  to pass validation. `validate` is available for complex drafts.
- Fix reported errors together by path; never guess alternate JSON dialects.

## Essential contract

`catalog` is an integer (currently 3), `layout` a nonempty array. Lists live in
`state`: `{"meals":{"type":"list","item":{"name":"string","kcal":"number",
"date":"date","shot":"image"},"max":200}}`. Max list size is 200; do not promise
unlimited retention. Arithmetic is a STRING: `{"expr":"max(0,goal-total)"}`.
Binds are scalar key strings (`"value":"total"`), never `{ref:...}` objects.
Headers use `text`, capture uses `photo` with `vision`, not guessed aliases.
Prefer `form`, `list_row`, `tracker_card`; totals/charts must read the same list.
Keep photos/dates, manual entry, empty copy, and seeded row edit controls.
Never fill real state with synthetic sample data.

For an advanced feature absent from guide, read only the linked reference via
`skill_view(name="flowlets", file_path="references/catalog.md")`.
